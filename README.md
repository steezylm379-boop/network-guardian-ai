# Network Guardian AI — Phase 3

Android-first Flutter LAN inventory with deterministic device intelligence and a grounded local AI network assistant.
Version 1.3.0+5 adds **Ask Your Network**, **AI Network Doctor**, Guardian insights, local chat/diagnostic persistence, and an enterprise AI privacy/gateway contract on top of the Phase 1/2 scanner and fingerprinting foundation. The default assistant does not require a cloud LLM and does not upload the local network inventory. See `PHASE3_STATUS.md` for the exact implementation and verification state.

## Phase 3 — grounded network intelligence

Phase 3 deliberately separates **telemetry** from **narration**. Device inventory, identity evidence, scan history, device events and diagnostics form a structured local context. The assistant answers only from that context and exposes evidence with its responses. Unsupported questions, including per-device bandwidth or a blanket "is my network secure?" verdict, are answered with an explicit limitation instead of invented data.

`Guardian AI` adds:

- Ask Your Network conversations stored locally per network.
- Queries for connected/unknown/offline/new devices, camera/NVR profiles, router identity and recent changes.
- Network Doctor checks for gateway latency/loss, Android Internet validation, DNS configuration and scan freshness.
- Guardian Insights that summarize meaningful local changes without calling unknown devices malicious.
- Drift schema v3 for local assistant messages and diagnostic reports.
- `EnterpriseAiGateway` and `AiPrivacyPolicy` contracts for a future company-controlled model backend. Raw IP/MAC fields are redacted by default and no vendor model API secret belongs in the mobile app.

This exact v1.3.0+5 checkpoint is **source-implemented but not yet build-verified**. Run `tool/verify_phase3.ps1` after extraction. Physical LAN validation remains separate because an emulator cannot prove real LAN discovery.

## Architecture

- `core/network`: platform adapter, subnet arithmetic, offline OUI lookup.
- `features/network_scan`: identity merger and Riverpod scan lifecycle.
- `features/devices/domain`: device identity and observations.
- `core/database`: Drift schema, isolated SQLite execution and atomic snapshots.
- Android `DiscoveryBridge.kt`: network information, bounded reachability pool,
  best-effort ARP, DNS PTR queries and network-bound NSD discovery.
- Flutter Material 3 presentation: charcoal surfaces, restrained sage accent,
  overview, device list, details and optional Wi-Fi identity permissions.

Each device has a UUID independent of its current IP. Phase 2 reconciliation uses
strong protocol identifiers and global MAC, then provisional IP. Conflicting strong
identifiers are never merged. Weak hostnames alone at different IPs do not merge. mDNS
service instance names are stored as labels, **not** trusted as globally unique
physical identities. Multiple mDNS services at one IP enrich one device record.
MAC-less devices without stable protocol identifiers can remain ambiguous after DHCP changes.

Networks use BSSID when Android exposes it, plus CIDR and gateway. Without BSSID,
the boot count and Android network handle scope the history; SSIDs are never
assumed globally unique. This conservative fallback can create separate histories after Wi-Fi
reconnects. Roaming to another AP can
also create a separate network history. See status for verification limitations.

## Discovery and privacy

Only the currently attached Wi-Fi IPv4 subnet can be submitted to the native
scanner. There is no remote target input. Prefixes are calculated from Android
LinkProperties, including /31 and /32. Networks over 4,096 usable addresses are
refused explicitly rather than silently narrowed to /24.

At most 32 addresses run concurrently. Reachability uses Java's interface-scoped
ICMP/reachability facility, followed by network-bound TCP connects to 80 and 443.
A successful connection or explicit ECONNREFUSED is a positive observation.
Timeouts are never counted as devices. No application payload is sent.

Reverse DNS is a bounded UDP PTR query to the selected Wi-Fi network's DNS server.
The resolver may forward queries upstream according to router configuration.
ARP reads are best effort: Android generally restricts `/proc/net/arp`; cached
entries only enrich already observed devices and never prove current presence.
No root or hidden API is required.

NSD browses `_airplay`, `_googlecast`, `_printer`, `_ipp`, `_http`, `_https`, and
`_workstation` TCP service types for an eight-second window. Resolves are serialized
for Android compatibility and have a bounded queue drain. Service TXT values are
stored as Base64 to preserve arbitrary bytes. Service presence is an observation,
not proof of manufacturer, product type or security.

Address progress is actual completed-address count. Name/service resolution is a
separate stage. UI snapshots are throttled to 180 ms. SQLite runs in an isolate;
each final device snapshot and session result are saved in one transaction.
Completed scans mark unseen historical devices offline; cancellation and failure
retain prior status. An app termination marks an unfinished session interrupted
on next database open. In-flight observations are not crash-durable before save.

Cancellation closes active sockets, interrupts workers, stops discovery, and
ignores late events by run ID. Android 13's NSD resolution and Java ICMP calls
cannot always be forcibly interrupted; they are bounded and late results ignored.

## Android permissions

- INTERNET: LAN sockets, DNS and discovery.
- ACCESS_NETWORK_STATE: select Wi-Fi and read LinkProperties.
- ACCESS_WIFI_STATE: optional Wi-Fi identity.
- ACCESS_COARSE_LOCATION / ACCESS_FINE_LOCATION: requested together only when the
  user taps the optional identity permission button. Precise location and enabled
  location services may be needed for SSID/BSSID. No location coordinates are read.

Android 13+ requests `NEARBY_WIFI_DEVICES` alongside the optional location permissions used for Wi-Fi identity. NSD is managed by Android. Phase 2 SSDP uses a scan-scoped multicast lock with
CHANGE_WIFI_MULTICAST_STATE. LAN HTTP is enabled for UPnP descriptions, with strict
application-level responder/subnet URL validation. No arbitrary browsing flow exists.
Target SDK is 35. Android 16 opt-in LAN restrictions and Android 17 target-SDK
permission changes require additional qualification before raising the target.

Sources: [Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd),
[Android local network permissions](https://developer.android.com/privacy-and-security/local-network-permission),
[Drift native setup](https://drift.simonbinder.eu/platforms/vm/).

## Offline vendor data

`assets/oui.json` is generated from the public
[IEEE MA-L registry](https://standards-oui.ieee.org/oui/oui.csv).
The source snapshot is included for traceability. Locally administered, multicast,
redacted and unknown MACs show “Unknown manufacturer”. MA-M/MA-S are not bundled;
the lookup code supports longest prefixes if those datasets are added later.
This identifies an assigned organization, never an exact product model.

## Physical-device testing

**NOT VERIFIED ON PHYSICAL DEVICE** until an actual device run is recorded in
PHASE2_STATUS.md. An APK build or emulator launch cannot establish LAN discovery.

On Android 13, 14 and 15, test with several awake LAN peers and a known mDNS
advertiser. Compare with router leases and direct peer responses; sleeping,
firewalled and client-isolated peers are not guaranteed discoverable.

1. Launch offline from the Internet but connected to LAN; inspect actual IP,
   prefix, gateway, host range and optional SSID.
2. Scan a /24 and a non-/24 network. Verify progress and smooth scrolling.
3. Confirm several peers and an advertised service. Inspect all detail fields.
4. Cancel early and during resolution; re-scan immediately. Check no late results
   leak into the next scan and old devices are not all marked offline.
5. Deny optional permission, then grant precise permission with location enabled.
6. Disconnect Wi-Fi mid-scan and change networks; ensure results stay separated.
7. Force stop/relaunch after save; verify IDs, firstSeen, lastSeen and services.
8. Remove a previously responding peer, complete scan, verify offline history;
   restore peer and confirm lastSeen advances without resetting firstSeen.
9. Test DHCP address changes with and without visible MAC addresses.
10. Record OS/build, device, router, peer ground truth and observed limitations.

Debug logs contain event categories, not raw addresses, MACs or TXT records.
Release code emits no scan debug logs. SQLite history is local and Android backup
is disabled because network identities can be sensitive.

## Phase 2 architecture and policy

`features/intelligence/domain` contains identifiers, evidence, fingerprints,
overrides, collection, reconciliation and the deterministic classifier.
`IntelligenceParsers.kt` parses SSDP/UPnP; `DeviceIntelligenceDiscovery.kt` binds
discovery to selected Wi-Fi; `LanDescriptionClient.kt` bounds and cancels HTTP.
Riverpod batches dirty classification in 180 ms snapshots. The identity panel,
evidence sheet and correction dialog extend the existing visual system.

Drift schema v2 adds identifiers, evidence, fingerprints, overrides and possible
matches without deleting Phase 1 networks/devices/services/sessions. Legacy payloads
are backfilled from their original timestamps on load. Final scan snapshots remain
transactional. Corrections are saved independently and survive rescans/restarts.
Use `adb install -r` to update a debug installation without deleting its database.

UPnP UDN stability is 95, global MAC 85, scoped protocol identity 80–85, private MAC
35 and hostname 25. Strong conflicting identifier sets always remain separate,
including when another identifier matches. Weak matches at different IPs create
informational possible-match links. IP-only attachments are provisional; later
conflicting identifiers restore historical records. Without identifiers, IP reuse
cannot be proved. Manual merging of possible matches is not included.

Evidence preserves source, original/normalized value, weight, first/last seen,
expiry, observation count and protocol scope. Duplicate fields in one scan do not
inflate counts. TXT keeps Base64 bytes and separately stores safely decoded text.
Only documented protocol/key combinations contribute model clues. User corrections
take precedence, become persistent user evidence, and have an explicit clear action.
Renames never erase protocol names or hostnames.

Expiry: IP/gateway/ports/SSDP/private MAC 1 day, mDNS service/name 3 days,
DNS/TXT 7 days, OUI and UPnP 30 days. Stable identifiers retain historical identity;
user corrections do not expire. Expired evidence stays inspectable but no longer
contributes. Reevaluation runs on load, new evidence, correction and an idle
one-minute expiry check. OUI data is cached after its first load.

Explicit UPnP category/manufacturer/model scores 85, scoped TXT model 75,
printer service/OUI manufacturer 70, and generic hostname/port clues much less.
Model numbers are used only when no active model name exists. Reported strings
are displayed without inventing product mappings. Repeated fields from one source
cannot accumulate unlimited confidence; another source adds at most 15 points,
with automatic scores capped at 95. Significant conflicting candidates are retained
and reduce automatic confidence to at most 39. OUI alone never selects a category icon.

**Evidence strength is not probability.** HIGH >=80, MEDIUM >=55, LOW >0,
UNKNOWN 0. CONFIRMED (100) requires explicit user confirmation of a known identity
detail. Overall strength summarizes available evidence; it does not make every
field equally reliable. The evidence sheet exposes individual candidate scores,
reasons, conflicts, sources and expiry. Advertisements can be incomplete or spoofed;
device identification is not authentication.

## Phase 2 discovery bounds

SSDP sends two M-SEARCH requests to 239.255.255.250:1900 (`ssdp:all`,
`upnp:rootdevice`, MX 2), with 3.5 seconds reception, 128 responses, 8 KiB headers
and 32 unique LOCATION URLs. UPnP uses four workers, 800 ms connect/read timeouts,
a 12-second batch deadline and 128 KiB response limit. URLs must be HTTP(S), have
no credentials/fragments, and use a numeric IPv4 host equal to the responder and
within the selected subnet. All redirects are rejected. DNS aliases and proxy
descriptions are intentionally skipped. TLS verification remains enabled.

XML is strictly UTF-8 decoded once; NULs and DTD/entity declarations are rejected
before parsing the same characters. External entity resolution is rejected.
Malformed/unsupported encodings are skipped. Root device fields are not mixed
with embedded-device models. Scripts and service/control/presentation URLs are
never executed or fetched. No authentication attempts occur.

TCP hints connect only to selected ports 22,53,80,443,445,554,631,8008,8009,9100,62078
on discovered hosts: four workers, 200 ms connects, ten-second deadline, 128-host
cap. Only successful connects count as open ports; no application commands or
web crawling are added. Hosts can receive no hints when limits are reached.
NSD now caps its queue at 128 distinct services. Cancellation/network changes
close sockets, disconnect descriptions, stop workers and reject late results.
Secondary identifying phases use indeterminate progress; host counts remain real.

Protocol reference: [UPnP Device Architecture](https://upnp.org/specs/arch/UPnP-arch-DeviceArchitecture-v1.1.pdf).

this warning does not prevent generation.
